# Теплотрасса TREE 1.4.1 REFRESH — отдельная сборка без старого кеша

Новая стратегия сначала строит обзорный граф свободной территории, затем сравнивает несколько частичных деревьев и продолжает сеть из существующих линий и уже построенных ветвей. В конце она пробует переподключить наиболее дорогие ветви. Полный допустимый результат принимается только после пересчёта всей сети.

В архиве исходники, готовый JAR, встроенная модель выбора подключений, тесты и результаты проверки. Диффузионной нейросети в этой версии **нет**: проект её объединения с деревьями описан в `docs/HYBRID_DIFFUSION_TREE.md`. Python и GPU для приложения не нужны.

## Что изменилось в 1.4.1 REFRESH

Новое имя архива и папки, отдельная страница `/tree-1.4.1`, новые имена JS/CSS/HTML. Сервер отдаёт `Cache-Control: no-store`. Страница проверяет идентификатор сборки перед расчётом и показывает версию сервера; при несовпадении новый расчёт не запускается. В JSON и GeoJSON добавлен блок `application` с версией и buildId. У скачанного отчёта в имени теперь есть `1.4.1`.

Алгоритм, веса, инженерные правила и ключи накопленного опыта те же, что в 1.4.0. Это сборка для устранения путаницы версий, её нельзя считать новым экспериментом по качеству маршрутов. Проверка запуска и кеша — `validation/refresh/RESULTS.md`; данные маршрутов 1.4.0 сохранены в `validation/tree`.

## Запуск и обновление

Из папки с `docker-compose.yml`:

```bash
docker compose -p teplotrassa-rl up -d --build --force-recreate
```

Откройте **http://localhost:8081/tree-1.4.1**. В шапке должно быть **«1.4.1 REFRESH · карта коридоров и деревья»**, ниже — **«TREE 1.4.1 REFRESH · сервер 1.4.1 подтверждён»**. Если новый адрес даёт 404, на этом порту работает другая сборка: проверьте, что команду выполнили именно из новой папки. Другой порт: `PORT=8082` в `.env`, тогда замените 8081 в адресе.

Для продолжения прежнего опыта используйте **то же имя Compose-проекта**, прежние `.env`, тома БД и расчётов и cookie браузера. Если раньше имя отличалось от `teplotrassa-rl`, подставьте его. Новое имя проекта создаст отдельные тома. Не выполняйте `docker compose down -v`, если нужны сохранённые данные. При первой сборке необходим интернет для образов и Maven-зависимостей.

Правила, исходная RL-модель и ключи опыта совместимы с **1.3.0 и 1.3.1**. Изменение четырёх настроек дерева не сбрасывает опыт. Повторно загрузите тот же файл без изменения его байтов и используйте те же инженерные параметры. Сам ZIP личные накопленные веса и БД не содержит.

Готовый JAR запускается на Java 11+ с заранее созданной PostgreSQL:

```bash
export DATABASE_URL=jdbc:postgresql://localhost:5432/teplotrassa
export DATABASE_USER=teplotrassa
export DATABASE_PASSWORD=teplotrassa_local
java -Xmx6g -jar release/teplotrassa-server-1.4.1-tree-refresh.jar --server.port=8081
```

Для прямого обновления сохраните прежние БД и `DATA_DIR`.

## Где менять новые параметры

В **«2. Настройки расчёта» → «Алгоритм» → «Карта коридоров + поиск деревьев»**. Этот режим выбран по умолчанию.

| Параметр | По умолчанию | Значение |
|---|---:|---|
| Деревьев на каждом уровне | 4 | Число сохраняемых вариантов после подключения очередной точки |
| Продолжений для каждого дерева | 3 | Максимум различных успешных продолжений одного варианта |
| Проходов перестройки ветвей | 1 | Сколько раз пересматривать выбранные ответвления; 0 отключает улучшение полной сети |
| Ветвей для пересмотра за проход | 4 | Сколько наиболее дорогих подключений пробовать построить заново |
| Число кандидатов врезки | 8 | Размер набора возможных мест присоединения |
| Сохранять и использовать опыт | Включено | Загрузка прежней модели и лучших сетей, сохранение лучших полных результатов |

Больше деревьев и продолжений расширяют поиск и увеличивают время. Начните с 4 / 3 / 1 / 4. Для более широкого поиска можно попробовать 8 / 4 / 2 / 6 и сравнить абсолютный score и время на том же файле. Улучшение от увеличения чисел не гарантировано.

В режиме дерева число эпизодов RL не применяется. Веса используются для порядка рассмотрения подключений и **не обновляются**. Поэтому счётчик обучения может не увеличиться, хотя новые деревья проверены. Состояние Adam и незавершённый пакет RL сохраняются без изменений. Для обновления весов выберите прежний режим **«RL — обучение с опытом»**; его параметры и поведение описаны в `docs/README_1.3.1_HISTORY.md` и `docs/EXPERIENCE.md`.

Поиск дерева детерминирован при одинаковых данных, весах и настройках. Повтор того же запуска не создаёт новые случайные эпизоды. Дальнейшие изменения могут появиться при перестройке сохранённой сети, увеличении ширины поиска или после отдельного обучения RL.

## Что действительно изменилось

1. **Обзор всей области.** Граф свободных коридоров покрывает прямоугольник всех вводов и существующей сети с запасом 80 м. Из него выделяется остов и удаляются тупики без контрольных точек. Его расстояния и остов помогают выбирать продолжения. Трубы не копируют линии этой сетки.
2. **Несколько начал и продолжений.** Сохраняется несколько деревьев. Следующая точка может подключиться к узлу, середине новой ветви или существующей сети. Для новой ветви проверяются ближайшая проекция, соседние позиции и концы с учётом лимита кандидатов. Ближайшее по прямой место не обязательно даст лучший допустимый маршрут.
3. **Перестройка.** Из полной сети временно удаляется одно подключение, удаляются его ненужные участки, затем оно строится заново. Принимается только полная сеть с меньшим score после пересчёта диаметров, стоимости, углов и глубины. При неполном результате есть ограниченная попытка перестроить соседнюю ветвь для доступа к пропущенной точке.
4. **Объяснимый результат.** Блок «Как изменилось дерево» показывает размер графа, количество продолжений и отказов, принятые улучшения и score до/после. Подробности находятся в `search.treeSearch` JSON-отчёта. Сохранённый лучший результат возвращается, если новые варианты его не превзошли.

## Правила и ограничения

Все исходные точки обязательны и неподвижны. Для каждой внутренней точки закреплена ближайшая наружная стена; прочие стены остаются препятствиями. Прямая не штрафуется; 90° — 25, 45° — 50, 135° — 75 условных метров. Штраф не входит в денежную смету. Общие ветви учитываются один раз, их DN соответствует суммарному расходу. В интерфейсе оценка 70% стоимости и 30% длины с поворотами; **меньше score — лучше**. Сравнивайте одинаковые данные и инженерные настройки.

Обзорный граф грубый: при лимите узлов шаг увеличивается. Он может не заметить узкий проход; его прогноз не используется как запрет точного маршрута. Это эвристика, а не гарантия минимальной сети или нахождения всех допустимых подключений. Ширина поиска и число кандидатов ограничены; неудача поиска не доказывает физическую невозможность подключения. Глобальный минимум и преимущество скорости не доказаны.

Правило стены сохранено. В частности, отклонение ввода №10 от перпендикуляра связано с коротким выбранным сегментом фасада и отступом коридора от его концов. Эта версия не объединяет сегменты фасада и не обещает устранить этот наклон. Такое изменение требует отдельной геометрической доработки и новой проверки совместимости опыта.

Реальная карта в примере использует сценарную загрузку старой сети 50%; её показатели не являются подтверждённой сметой объекта. Полный гидравлический расчёт и измеренные отметки коммуникаций не добавлены.

## Проверка и материалы

```bash
mvn -f server/pom.xml test package
mvn -f server/pom.xml -Dtest=TreeSearchTest#suppliedMapTreeSearch -DtreeSupplied=true test
```

Вторая команда выполняет длительную проверку 17 точек и записывает отчёт и GeoJSON в `validation/tree`. Актуальные измерения и ограничения стенда — `validation/tree/RESULTS.md`. Каталоги `validation/progress`, `validation/learning` и остальные старые отчёты описывают предыдущие версии.

- `START_HERE.md` — контекст для переноса в новый проект.
- `docs/TREE_SEARCH.md` — алгоритм и границы его применимости.
- `docs/HYBRID_DIFFUSION_TREE.md` — проект гибрида с диффузионной моделью.
- `docs/API.md` — параметры API; по умолчанию API сохраняет `classic`, новый режим нужно передавать явно.
- `release/manifest.json` — версия, хеши исходников и JAR, совместимость.

Совместимость старых ссылок: contest.html перенаправляет на новый адрес, прежний app.js содержит только переход к /tree-1.4.1, style.css импортирует новый файл стилей. Старой логики интерфейса в этих файлах нет.
