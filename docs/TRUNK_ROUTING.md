# Единое дерево и общие стволы · 1.7.0

## Что изменилось относительно 1.6.0

В режиме `routingStrategy=tree`, `treeSingleRootRequired=true` требуется одна общая врезка. После первого подключения продолжения присоединяются к новому дереву. Восстановленная сеть с несколькими корнями отклоняется с `SINGLE_ROOT_REQUIRED`. Если полная допустимая сеть не найдена, результат содержит диагностику, а не неполную сеть или несколько врезок.

В UI требование включено по умолчанию. API сохраняет прежнее поведение при отсутствии нового параметра; для единого дерева передавайте его явно.

## Последовательность поиска

1. Для каждой исходной точки закрепляется ближайший отрезок стены. С учётом минимального необходимого DN проверяется, позволяют ли направления конкретной врезки войти во все закреплённые окна. Проверяются существующие камеры и позиции на отрезках теплотрассы. Из совместимых позиций выбирается несколько пространственно различающихся кандидатов. Угловая совместимость — необходимое условие, а не доказательство существования полной трассы.
2. Для каждого выбранного корня строится повёрнутая карта проходов. В координатах присутствуют корень, наружные подходы к вводам, границы обхода зданий и регулярная сетка. Коридоры предварительно проверяются на габарит для общего расхода; это консервативное приближение. Для узких коридоров оно может пропустить допустимый маршрут меньшего DN.
3. Многoисточниковый поиск кратчайшего присоединения стартует из всех доступных вершин растущего дерева, включая промежуточные вершины вдоль участков. Уже проложенные общие участки не оплачиваются повторно в длине нового присоединения. Сравниваются ближайший к дереву ввод, дальние вводы сначала, большие расходы сначала и начала с каждого из исходных вводов с последующим присоединением ближайших к дереву. Учитывается доступная степень камеры; циклы не создаются.
4. Полученная общая сеть проходит точную проверку. Короткие выходы из узких закреплённых окон рассчитываются точно перед построением карты. Если ни одно предложение не дало полного дерева, точный поиск дополнительно достраивает подходы в трёх лучших допустимых частичных сетях с прежними правилами стен. Промежуточная неполная сеть не становится результатом. Если подходящих полных деревьев нет, выполняется резервный поиск частичных деревьев с сохранением разнообразия корней.
5. Дополнительная оптимизация (отдельный переключатель, по умолчанию выключен) переносит целые поддеревья за общий ствол и совместно перестраивает группы до 6 потребителей. Для больших поддеревьев сохраняется перенос общего ствола. Для групп проверяются общие узлы соединения и иерархическое разбиение; для небольших групп сохранён прежний метод перестройки. Неиспользованные тупики удаляются. Принимается только полное допустимое улучшение итогового score.
6. Все полные кандидаты проверяются по пересечениям, закреплённым стенам, исходным координатам, расходам, DN, длинам, степени камер, реконструкции и выбранному режиму глубины. Геометрические ошибки промежуточных графовых кандидатов записываются в диагностику; такой кандидат не публикуется.

Начальные направления сетки ортогональны выбранной врезке. Точный поиск подхода допускает каталог 45/90 градусов. Прямой участок предпочтителен; действуют прежние штрафы: 90° — 25 эквивалентных метров, 45° — 50, 135° — 75. Эти метры участвуют в score, но не добавляются к физической длине и смете.

## Диагностика и интерфейс

`search.treeSearch.rootSelection` содержит проверенные/совместимые места, выбранные позиции и вводы, блокирующие другие направления. `corridorTrees.trials` содержит корень, порядок, число подключённых точек, необходимость точного поиска подходов и причины отклонения. `sharedOptimization` содержит сравнения схем, переносов стволов и групп.

`search.entryAssignments` дополнен `wallSegmentLengthM` и `usableWallLengthM`. Последнее — длина окна при минимальном DN конкретного ввода; финальный DN и фактический вход проверяются отдельно. На предоставленной схеме у ввода 10 исходный фрагмент стены около 1,803 м, доступное окно при DN125 около 1,203 м. Стена не расширяется искусственно.

В UI видны номера вводов, общая врезка и отдельные значения новой длины и реконструкции. Панель расчёта объясняет, был ли выполнен поиск на карте проходов, резервный поиск или продолжение сохранённого результата.

## Обучение и память

По умолчанию UI выключает автоматическое обучение, чтобы сначала использовать геометрический поиск. Обучение остаётся опциональным: модель задаёт порядок продолжений резервного поиска; копия весов обучается на сравнении проверенных полных сетей в одинаковых состояниях и принимается после проверки качества. Этап общего графа/групп не подменяет результат контрольного прохода модели. Новые обучающие сравнения после перестройки сохраняются для следующего расчёта.

Сохранение лучших сетей работает и без обучения. Для обязательной одной врезки используется отдельный ключ опыта; записи прежнего режима, веса и результаты не удаляются. Переноса прежних весов в новый режим автоматически нет. Появление новой записи не означает потерю старой памяти.

Это гибрид геометрического графа, поиска деревьев и необязательной обучаемой политики. Диффузионной нейросети в сборке нет. Изменение весов или относительная оценка 100 не доказывают улучшения. Сравнивайте абсолютный score, физическую длину, стоимость, полноту и время при одинаковых условиях.

Поиск конечный по числу кандидатов и настроенным проходам; общего временного лимита нет. Он не доказывает глобальный оптимум или невозможность решения, если кандидаты закончились.
