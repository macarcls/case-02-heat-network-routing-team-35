# RL-среда и история первоначального обучения

В 1.3 добавлено обучение во время расчёта и постоянный опыт. Актуальная логика обновления и восстановления описана в `EXPERIENCE.md`. Ниже — устройство среды и протокол начальной модели v1.2.

## Задача и среда

Эпизод начинается с пустой новой сети поверх существующих теплотрасс и заканчивается, когда подключены все вводы либо исчерпаны доступные действия. Состояние включает построенные ветви, оставшиеся вводы, расходы, закреплённые ближайшие стены и окружение. Конкретное действие — пара «неподключённый ввод + место присоединения». Цель может быть существующей трубой/камерой, новым узлом или точкой на новой ветви. Поэтому выбор меняет топологию, а не только порядок перебора одних и тех же кандидатов.

Кандидаты предварительно фильтруются по отступам, допустимости стены и доступности камеры. После выбора действия `Planner.addDemand(..., forcedTarget)` строит лучший из своих геометрических маршрутов к **выбранной** цели и проверяет всю пробную сеть через `Evaluation`. Нейросеть не подменяет расчёт маршрута, выбор DN, пространственные проверки или глубину. Непрошедшее действие удаляется только из текущего состояния; при добавлении новой ветви набор целей строится заново. Недоступный ввод нельзя пропустить и назвать результат полным.

Кэш переходов ограничен 512 записями на Planner и ключуется всей последовательностью успешных действий. В кэш попадают копии сетей; отменённые переходы не сохраняются. Кэш маршрутов повторно проверяет возможность использования пути с учётом новой сети. В RL действует независимая от истории запросов геометрия из предыдущего экспериментального движка (`off`). Прежний режим `classic + baseline` оставлен для сравнения со старой версией.

## Модель

Общая для всех действий MLP: 32 признака → 32 tanh → 1 логит. 1 089 обучаемых параметров. Признаки содержат длину направления, ориентацию принимающей трубы, характеристики стены и препятствий, тип цели, текущую сеть и симметричную сводку оставшихся вводов: расстояния, близость к будущей ветви, долю расхода и прогресс подключения. Идентификаторы объектов и абсолютные координаты в модель не подаются. Это не GNN и не анализ изображения карты.

Вход ограничивается диапазоном [-8,8]. При температуре T>0 вероятность действия пропорциональна `exp(logit / T)`; при T=0 выбирается максимальный логит. Порядок разрешает равенство детерминированно. Первый поисковый эпизод всегда жадный, остальные используют настройку температуры и генератор `java.util.Random` с указанным seed. Веса и порядок признаков проверяются при загрузке. При отсутствии/неверной модели RL возвращает понятную ошибку и не маскируется классическим алгоритмом.

Встроенный файл — `server/src/main/resources/models/reinforcement-policy.json`. При необходимости `TEPLOTRASSA_RL_MODEL` указывает серверу другой локальный JSON в том же формате. Загрузка происходит при старте; после замены файла сервер нужно перезапустить. При запуске в контейнере внешний файл должен быть смонтирован в контейнер.

## Награда и обучение

Пусть N — число обязательных вводов, C — число подключённых, S — оценка **всей** сети. S включает нормализованные стоимость и длину с выбранным профилем и штрафы поворотов. В обучении используется только профиль appendix: 70% стоимости / 30% длины. В стоимость входят общие ветви с суммарными расходами, DN, спецпроходы, глубина, камеры, врезки и реконструкция.

```text
q = S / max(1, N)
R = -q / (1 + q)                  если C = N
R = -2 - (N - C) / max(1, N)     если C < N
```

Полная сеть имеет R в (-1,0], неполная — в [-3,-2). Поэтому экономия на пропущенном вводе никогда не улучшает награду. Среди полных сетей преобразование строго сохраняет порядок S на одном наборе. На промежуточных шагах награда равна нулю; итоговая награда обучает все выборы эпизода. Отдельного денежного штрафа за неподключение в отчёте нет.

Награда обучения и `attempts[].reward` оценивают сеть до заключительного `smoothNetwork`. После эпизода готовые сети дополнительно упрощаются и проверяются тем же механизмом, что в классическом поиске; итоговый список ранжируется по фактическому S после упрощения. `scoreBeforeSmoothing` позволяет видеть эту разницу.

Обучение: REINFORCE, 12 эпизодов одной территории на обновление, baseline — средняя награда остальных 11 эпизодов. Преимущество масштабируется на `max(0.025, std(rewards))`. Добавлена энтропия с коэффициентом 0.01. Оптимизатор Adam, шаг 0.003, норма градиента ограничена 1. Все производные реализованы NumPy; корректность проверяется численным дифференцированием.

3840 эпизодов / 320 обновлений, seed=71. 24 обучающих квартала (0–23), 8 валидационных (24–31), 16 тестовых (32–47). Генератор вызывается с offset 1000: 3–4 ввода, прямоугольные здания, поворот карты, разные расходы, иногда препятствия/дороги; каждая третья сцена считается с глубинами. Обучающий лимит целей — 2, gridM=20. Переходы выполняет настоящий Java-движок; используется мемоизация повторных префиксов, а не приближённый растровый симулятор.

Checkpoint выбирается только по средней жадной награде на валидационных кварталах. Выбран update 60 (720 эпизодов к этому моменту); тестовые кварталы и пользовательская карта при выборе не использованы. Полный протокол — `validation/rl/training/training-report.json`, начальные/последние/лучшие веса сохранены рядом. Java и NumPy сопоставлены на 40 контрольных предсказаниях.

## Повторение проверок

Сначала собрать сервер и задать JAVA_HOME на JDK 11+ при необходимости:

```bash
mvn -f server/pom.xml test package
python -m pip install -r tools/rl/requirements.txt
python tools/rl/test_training.py
python tools/rl/runtime.py benchmark validation/rl-recheck 32 16
python tools/rl/runtime.py supplied validation/rl-recheck 12
```

`benchmark` сравнивает обученную и исходную необученную MLP на одинаковых 6 эпизодах, seed, температуре, геометрии и лимите целей. Классический алгоритм также приведён как ориентир; при variantLimit=1 он обычно останавливается после 2 полных попыток и проверяет все цели внутри шага. Это **не одинаковый вычислительный бюджет с RL**. Время одного прохода, особенно при параллельных процессах, не доказывает ускорение.

Исходный пользовательский набор: `examples/supplied.geojson`, режим depth, scenario, недостающая загрузка 50%, gridM=20, candidateLimit=8, rlEpisodes=12, seed=71, T=0.7. Независимая проверка на Python/Shapely использует `validation/verify_nearest_turns.py --output-name rl/supplied-rl --report-name rl/independent-check.json`.

## Ограничения и развитие

- Возможности определены генератором целей и геометрическим поиском. Модель не может выбрать действие, которого нет в этом наборе.
- Нет действий отмены и перепрокладки выбранной ветви. Альтернативы исследуются новым эпизодом.
- В 1.3 обучение включается `rlLearning=true`, сохранение — `rlRemember=true`; оба флага включены в интерфейсе.
- Признаки сводят оставшуюся территорию к небольшому вектору. Обучение на 3–4 вводах не гарантирует переноса на 17, 100 или сложные дворы.
- Конечное число эпизодов и grid/maxCells — ограничения полноты поиска, хотя тайм-аута нет. Оптимальность не доказана.
- Гидравлический расчёт, грунты и тепловая компенсация не добавлялись.

Следующий содержательный шаг — более разнообразные обучающие территории и контроль переноса по числу вводов. Затем действия перепрокладки и графовое представление состояния. Увеличение числа эпизодов само по себе не исправляет отсутствующие коридоры или неподходящие инженерные исходные данные.
