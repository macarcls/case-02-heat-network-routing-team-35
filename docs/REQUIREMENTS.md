# Соответствие требованиям и вопросы организаторам

Основания: «2. ДИТ(1).pdf», «Техническое приложение(1).docx», протокол от 16.09.2026 и таблица критериев оценки. Версия 1.1.0 поддерживает горизонтальный первый этап и второй этап с глубиной на плоской поверхности.

## Реализация

| Требование | Реализация | Проверка |
|---|---|---|
| Java 11, Spring Boot 2.6.3, Spring Data | Maven parent 2.6.3, release 11, Spring Data JDBC для заданий, пакетный JDBC для геометрии | Компиляция и запуск на JDK 11 |
| PostgreSQL, Swagger 1.7.0 | PostgreSQL 16 в Compose; springdoc-openapi-ui 1.7.0 | API-тест Swagger; интеграционные тесты БД используют H2 |
| Ubuntu 22, docker-compose 1.29.2 | Runtime `eclipse-temurin:11-jre-jammy`, compose 3.8 | 1.0.0 запущена пользователем; образ 1.1.0 в текущей среде не запускался |
| Один экземпляр, офлайн | Два вычислительных потока, ограниченная очередь, локальные справочники и UI | API проходит без внешних ресурсов |
| Обработка до 3 ГБ | Потоковый приём на диск, Jackson по Feature, ограничение пакета по памяти, PostgreSQL | Отдельная проверка чтения 3 ГиБ; это не нагрузочный городской прогон |
| Выход до 500 МБ | Потоковая запись и скачивание, контроль размера и атомарная публикация файла | Малые результаты проверены; полный файл 500 МБ не генерировался |
| До 50 пользователей | 100 HTTP-потоков, 2 вычислительных работника, очередь 100; отдельные рабочие сессии | Статус нагрузочного прогона см. VALIDATION.md |
| Точки подключения | Конец трубы совпадает с исходной точкой; разрешён только прямой конечный вход через назначенный участок стены, с включением в расчёт | BuildingRoutingTest; независимая проверка GeoJSON |
| Совместная сеть | Лес, общие ветви, камеры в разветвлениях; единственный путь к потребителю | Проверки графа, расходов и экспортных ссылок |
| Расход и DN | Сумма потребителей, одна пара труб, таблица DN | Граничные и расчётные тесты |
| Предельная длина | Связные компоненты одного DN, сумма ветвей, одно повышение | Тесты разветвления, камер без сброса и запрета второго повышения |
| Камеры и врезки | Правило 10 м, не более 4 лучей, отдельная цена каждой врезки | Тесты сметы и реконструкции камер |
| Реконструкция | Событийное суммирование расходов на частях исходных труб до источника | Тесты нескольких врезок и обратного направления геометрии |
| Пространственные ограничения | Габариты и отступы, спецпроходы, max коэффициент перекрытия | JTS и независимая проверка экспорта |
| Полные варианты | До 3 различных полных сетей; многостартовый поиск, диагностика без выдачи частичных сетей | Автоматический прогон и отчёт |
| Дополнительный этап по глубине | Непрерывные профили, переходы, уклон, общий узел, цена и Z | 15 тестов DepthTest, API depth, независимая проверка сохранённых результатов |

## Критерии оценки

| Критерий | Что демонстрировать |
|---|---|
| Подход команды | Сравнение полной стоимости отдельных и совместных подключений, выбор врезок с учётом реконструкции |
| Качество трассировки | Прямые линии, стандартные углы, штраф за поворот, отсутствие пересечений вне узла |
| Соответствие задаче | Все точки, таблицы расходов и DN, проверки длины, геометрия фактической реконструкции |
| Эффективность | Разложение цены, число врезок и камер, сравнение полных топологий, совместных ветвей и раздельных врезок |
| Техническая проработка | Потоковый импорт, ошибки данных, восстановление после перезапуска, тесты и универсальный формат |
| Варианты и объяснимость | До трёх вариантов и единая формула оценки; причины неподключения |
| Дополнительная ценность | Сценарии неизвестной загрузки, контроль полноты, воспроизводимый отчёт |
| Питч | Короткий цикл: загрузить → рассчитать → сравнить → выгрузить |

## Расхождения и принятые решения

| Вопрос | Приложение | Протокол | Поведение версии |
|---|---|---|---|
| Веса оценки | Цена 0,7; длина 0,3, дана формула | Перечислены длина и цена с весами 0,7 и 0,3 | По умолчанию явная формула приложения; профиль protocol переключает веса. Уточнить у организаторов |
| ОКС | Контур + точка | Дана конкретная точка, контур не влияет | По уточнению пользователя 17.09.2026 исходная точка обязательна как конец трубы. Для внутреннего потребителя разрешён вход через назначенный участок стены; транзит запрещён |
| Однотипные ветви | Непрерывная часть | При разветвлении длина суммируется, можно увеличить DN на одну номенклатуру | Сумма связной компоненты, не длиннейший путь; одно повышение |
| Наложение спецпроходов | Явно не раскрыто | Максимальный коэффициент | Max, без перемножения и двойного начисления |
| Неподключение из-за цены | В исходном документе предусматривался штраф | Новое требование пользователя: все точки обязательны | Экономическое неподключение исключено; неполные сети не ранжируются |
| Нестандартный отвод | Нет отдельного тарифа | Удорожание 1,5 раза | Такие внутренние отводы не используются; к принимающей оси подходят стандартными направлениями. Базу удорожания следует уточнить перед добавлением произвольных углов |
| Железная дорога | Нет строки railway в справочнике | Упоминается вариативность препятствий | Строгая диагностика, в исследовании — запрет и явно указанное допущение |
| Глубина | Минимальная глубина 0,7 м | 0,7 м названо отклонением от препятствия | Два явных depthRuleProfile: приложение либо зазоры max(0,7, табличный). Покрытие 0,7 м сохраняется в обоих. Окончательное правило должен подтвердить организатор |

Отдельно у организаторов нужны полный атрибутивный состав финального городского набора, текущие расходы существующих труб, явные связи к источнику, правило для railway и подтверждение трактовки `restriction/oks` с внутренними точками потребления. Без этих данных нельзя выдавать сценарную реконструкцию за точную стоимость реального подключения.
