# Теплотрасса RL 1.3.1 — видимый прогресс обучения

Модель теперь **обновляет веса во время расчёта**, сохраняет обучение между запусками и продолжает его при повторном расчёте того же участка. Лучшие полные сети сохраняются отдельно от весов и заново проходят инженерные проверки. Можно накапливать разные участки и обучать на них общую модель.

В архиве: исходники, начальная обученная модель, готовый JAR, инструменты проверки и инструкции. Python, видеокарта и внешние API для работы приложения не нужны.

## Запуск

Распакуйте архив. Из папки с `docker-compose.yml`:

```bash
docker compose -p teplotrassa-rl up -d --build
```

Откройте **http://localhost:8081**. В шапке: **«Прогресс обучения · 1.3.1»**. Если видна старая версия, обновите страницу с Ctrl+F5. Другой порт задаётся в `.env`: `PORT=8082`.

При обновлении сохраняйте прежнее имя Compose-проекта `teplotrassa-rl`: оно определяет постоянные тома. Не выполняйте `docker compose down -v`, если хотите сохранить расчёты и обучение. Новое имя проекта создаст отдельную базу и опыт. При первой сборке скачиваются Docker-образы и Maven-зависимости; затем расчёты выполняются локально.

Готовый `release/teplotrassa-server-1.3.1-rl-progress.jar` запускается на Java 11+ с отдельным PostgreSQL:

```bash
export DATABASE_URL=jdbc:postgresql://localhost:5432/teplotrassa
export DATABASE_USER=teplotrassa
export DATABASE_PASSWORD=teplotrassa_local
java -Xmx6g -jar release/teplotrassa-server-1.3.1-rl-progress.jar --server.port=8081
```

При таком запуске БД и пользователя нужно создать заранее. Compose делает это автоматически.

## Что означает прежняя оценка 100

В версии 1.3 рейтинг рассчитывался как `100 × лучший score / score варианта`. Поэтому лучший вариант каждого расчёта всегда получал 100 независимо от качества обучения. В версии 1.3.1 таблица показывает **сам score, меньше — лучше**, с шестью знаками после запятой при необходимости. Score сравнивается только для одинаковых исходных данных и инженерных настроек.

Блок **«Что изменилось за расчёт»** показывает:

- фактическое изменение числовых весов, число обновлений за запуск и за всё накопленное обучение;
- восстановилась ли сохранённая модель, сколько полных сетей загружено;
- лучший score до и после запуска, лучший score только новых попыток;
- улучшение в процентах, график лучшей сети и таблицу последних 20 эпизодов.

Фраза **«Веса изменились» не означает, что маршрут улучшился**. Если новый результат не превзошёл сохранённый, приложение прямо пишет «Лучший маршрут не улучшился» и показывает, что выдан сохранённый вариант. Незавершённый пакет из менее чем четырёх обучающих эпизодов не обновляет веса. Первый эпизод каждого запуска проверочный и в пакет не входит.

Если прежнего полного решения нет, сравнение начинается с первой полной попытки текущего запуска. Частичные сети не считаются готовыми вариантами. График относится к текущему запуску, а его начальная точка при наличии опыта — заново проверенная лучшая сохранённая сеть. История всех эпизодов доступна через «Отчёт ↓».

## Обновление с 1.3 без потери опыта

Версия 1.3.1 сохраняет прежний формат весов, версию инженерных правил, начальную модель и ключи совместимости опыта. Она добавляет диагностику; алгоритм обучения и целевая функция остаются прежними.

Обновите файлы проекта и выполните сборку с **тем же именем Compose-проекта**, которое использовали для 1.3. Если запускали командой выше, оно `teplotrassa-rl`. Сохраните прежние `.env`, тома БД и расчётов и cookie браузера. Новая папка с другим именем Compose-проекта может открыть пустую базу: такой запуск не продолжит предыдущие 300 эпизодов. Для прямого запуска JAR сохраните прежние БД и `DATA_DIR`.

После обновления проверьте в шапке **«Прогресс обучения · 1.3.1»**. Повторно загрузите тот же файл без изменения его содержимого и оставьте те же инженерные настройки. Для проверки продолжения достаточно 5 эпизодов: должны появиться сообщение о загруженной модели и увеличившийся общий счётчик. До такой проверки повторять 300 эпизодов не нужно.

## Где менять параметры

В блоке **«2. Настройки расчёта»**:

| Настройка | По умолчанию в интерфейсе | Действие |
|---|---|---|
| Алгоритм | RL — обучение с опытом | Можно выбрать классический поиск |
| Сохранять и использовать опыт | Включено | Загружает прежние веса и лучшие сети, сохраняет новые; работает и для классических сетей |
| Обучать во время расчёта | Включено | Обновляет веса на новых попытках текущего участка |
| Число эпизодов RL | 13 | 1 проверочная попытка и 12 обучающих |
| Разнообразие попыток | 0,7 | При обучении должно быть больше 0 |
| Эпизодов в пакете обучения | 4 | После четырёх обучающих попыток — одно обновление весов |
| Шаг обучения | 0,003 | Сила обновления; диапазон API больше 0 и до 0,01 |
| Начальное число (seed) | 71 | Вместе с сохранённым счётчиком определяет случайные попытки |
| Число кандидатов врезки | 8 | Ширина набора мест присоединения |

Пакет и шаг находятся внутри **«Разнообразие и повторяемость»**. Если завершено меньше четырёх обучающих эпизодов, обновлений пока не будет: пакет продолжится в следующем запуске. Изменение размера пакета или температуры сбрасывает только незавершённый пакет; веса и лучшие сети остаются.

Над результатом видны обновления весов за запуск и за всё обучение участка, число эпизодов в незавершённом пакете и количество восстановленных сетей. Отчёт содержит начальный и конечный SHA-256 модели, награды и историю обновлений. Первая жадная попытка не используется для обучения.

## Что происходит при повторном расчёте

1. Тот же GeoJSON и те же инженерные параметры находят прежний опыт, даже после повторной загрузки файла с новым именем.
2. Загружаются веса, состояние Adam, незавершённый пакет и счётчик попыток. Последовательность случайных действий продолжается.
3. Сохранённые сети заново проверяются по исходным точкам, ближайшим стенам, расходам, DN, пересечениям, стоимости и глубине.
4. Новые попытки добавляют решения и обучают модель. Пока прежняя полная сеть допустима, лучший возвращаемый результат по score не ухудшается относительно неё.

Идентичность входа определяется SHA-256 **байтов файла**. Изменение даже форматирования создаёт другой опыт. Изменение загрузки сети, правил, режима глубины, grid/maxCells или candidateLimit также создаёт отдельную запись. `variantLimit`, seed, число эпизодов и параметры обучения не меняют совместимость участка.

Опыт привязан к рабочей сессии браузера (`tt_workspace`) и хранится на сервере в `DATA_DIR/experience-v1`, в Compose — в постоянном томе `/data`. Для продолжения сохраняйте тома и cookie браузера. Очистка cookie открывает другое рабочее пространство, не удаляя прежние файлы. Для переноса между компьютерами нужны БД, том расчётов и cookie; один архив исходников накопленный личный опыт не переносит.

Кнопка отмены прерывает поиск. Завершённые эпизоды остаются сохранёнными; прерванный эпизод не обучает модель. Запись атомарная, есть контрольная сумма и предыдущая копия. Задания одного рабочего пространства используют опыт последовательно. После перезапуска создайте новый расчёт: прерванное задание не возобновляется само.

## Общая модель для разных участков

В блоке **«3. Накопленный опыт» → «Обучение на разных участках»** нажмите **«Обучить общую модель»**. Нужно минимум **2 разных обучающих и 2 проверочных файла**. Стабильное разделение по хешу назначает около 80% файлов в обучение, 20% в проверку; поэтому четырёх загруженных файлов может быть недостаточно. Смена инженерных настроек не превращает тот же файл в новый проверочный участок.

Один проход создаёт по пять новых попыток на каждом обучающем участке: одну жадную и четыре для обновления. Старые последовательности действий не переигрываются как свежий опыт. Проверочные участки не участвуют в обновлении общей модели; локальные веса этих участков в неё не копируются.

Прежняя и новая модели проходят по три попытки на каждом проверочном участке с одинаковыми seed и настройками, без сохранённых сетей. Новая модель принимается только при улучшении хотя бы одного проверочного результата и отсутствии ухудшений остальных. При отказе остаётся прежняя модель; причина и сравнение доступны в отчёте. Новая общая модель становится стартом для участков, ещё не имеющих своих обученных весов. Старые локальные веса продолжаются независимо.

Эта проверка ограниченная: она не доказывает улучшение на любых будущих картах. Для честной оценки используйте разные территории, а не копии одного GeoJSON с изменённым форматированием. Многократный подбор по одной проверочной группе может переобучить критерий отбора.

## Качество и ограничения

Сохраняются все требования: исходные точки обязательны и неподвижны; ближайшая стена фиксируется отдельно для каждой точки; прочие стены запрещены; штрафы поворотов — 90°: 25, 45°: 50, 135°: 75 условных метров. В интерфейсе оценка 70% стоимости / 30% длины, штраф поворотов не добавляется к денежной смете. Все выданные сети полные и проверенные. Также исправлена ориентация ответвления на изгибе новой трубы: используется входящий отрезок, а не среднее двух направлений; нестандартные углы присоединений отклоняются.

Обучение не гарантирует улучшения каждого запуска и требует дополнительных попыток. Модель выбирает ввод и место присоединения; геометрию строит точный движок. Она пока не умеет удалять ветви и не создаёт отсутствующие в генераторе коридоры. Глобальный оптимум не доказан.

Начальная модель осталась из v1.2: 32→32 tanh→1, обучена на небольших искусственных кварталах. Проверки отображения прогресса в **1.3.1** — `validation/progress/RESULTS.md`; проверки обучения и пользовательской карты в **1.3** — `validation/learning/RESULTS.md`; исторические результаты фиксированных весов v1.2 — `validation/rl/RESULTS.md`. Не следует приписывать улучшение только нейросети без сравнения с поиском при одинаковом общем времени.

Для независимого запуска отключите «Сохранять и использовать опыт». Чтобы сравнить с фиксированными весами, дополнительно отключите «Обучать во время расчёта». Ничего из сохранённого опыта эти переключатели не удаляют.

## Проверки и устройство проекта

```bash
mvn -f server/pom.xml test package
python tools/rl/runtime.py active-search validation/learning-recheck 5
```

Второй запуск команды продолжит опыт в указанном каталоге; для проверки с нуля укажите новый каталог. Нужен JDK 11+ в PATH или JAVA_HOME. Для независимой проверки GeoJSON установите зависимости из `validation/requirements-check.txt` и запустите `validation/verify_nearest_turns.py` с нужным `--output-name`.

`START_HERE.md` — контекст для нового проекта, `docs/EXPERIENCE.md` — устройство накопления опыта, `docs/REINFORCEMENT.md` — исходная RL-среда, `docs/API.md` — API. Прежние PDF и прочие протоколы сохранены как история; они не описывают новые переключатели.
