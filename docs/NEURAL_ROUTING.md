# Нейросетевой эксперимент для теплотрассы

20.09.2026. В этой поставке модель действительно обучена и встроена в Java-планировщик. Она включается явно параметром `neuralGuidance=on`; основной режим `baseline` сохраняет прежнее поведение, поскольку эксперимент не улучшил рабочий результат. Это первый ограниченный эксперимент: MLP ранжирует уже имеющиеся кандидаты подключения. Она не рисует сеть по изображению, не создаёт новые коридоры и не обучена на инженерских исправлениях пользователя.

## Что изменилось

Раньше для очередного ввода проверялись кандидаты в порядке расстояния, а из допустимых выбирался лучший по стоимости, длине и штрафам за повороты. В экспериментальных режимах перед трассировкой каждому кандидату назначаются две разные оценки:

1. **Аналитическая нижняя граница** полного индекса. Она проверяема и нужна для отсечения заведомо проигрышных вариантов.
2. **Прогноз MLP** превышения над этой границей. Он нужен только для порядка проверки.

Предположительно перспективный кандидат проверяется раньше. Кандидат пропускается только если его аналитическая нижняя граница строго хуже уже проверенного допустимого решения. Нейросетевое значение никогда не считается доказательством ни допустимости, ни невозможности подключения. При равных результатах сохраняется исходный порядок разрешения равенств. Ошибочная, отсутствующая или несовместимая модель заменяется аналитическим порядком. Ошибка вычисления признаков не удаляет кандидат.

Ближайшая внешняя стена каждого исходного ввода остаётся закреплённой, другие стены — препятствиями. Исходные точки не перемещаются. Прямая не имеет штрафа; повороты 90° / 45° / 135° дают 25 / 50 / 75 условных метров. Рублёвая стоимость и длина материала не содержат условный штраф. Обязательны все вводы, габариты, DN, длины компонент, реконструкция, глубины и уклоны. Поиск не имеет ограничения времени, ручная отмена сохранена.

## Модель и данные

| Свойство | Реализация |
|---|---|
| Модель | Полносвязная MLP: 22 входа → 12 ReLU → 1 линейный выход, 289 обучаемых параметров |
| Выход | `log1p(max(0, фактический индекс кандидата − нижняя граница))` |
| Ранжирование | Нижняя граница + `expm1` прогноза, ограниченного диапазоном 0…20 |
| Данные | 80 синтетических кварталов; 2 585 кандидатов, полученных полным обычным поиском |
| Разделение | 48 кварталов для обучения, 16 для выбора модели, 16 для окончательной проверки |
| Обучающие строки | 1 571; полностью недопустимые группы исключены из обучения |
| Учитель | Текущий геометрический планировщик с точными проверками, без нейросети и без отсечения |
| Обучение | sklearn 1.8.0, L-BFGS, `alpha=0.05`, seed 71; до 700 итераций |
| Исполнение | Java 11, встроенные JSON-веса; Python и GPU серверу не требуются |
| Реальный квартал | Все 17 вводов и исходная геометрия исключены из обучения и выбора гиперпараметров |

Признаки описывают расстояние, ориентацию относительно принимающей трубы, расход/DN, вид присоединения, текущую сеть, ближайшую стену, пересечения препятствий и занятых ветвей. Абсолютных координат, ID объектов и эталонного ответа в признаках нет. Генератор меняет размеры и положение прямоугольных зданий, стороны входа, препятствия, дороги, поворот всего квартала, расходы и профили расчёта. Все 80 учебных территорий удалось полностью подключить обычным алгоритмом. Это синтетические данные, не набор согласованных инженерных проектов. Учебные вводы расположены в 1 м от прямого фасада: разнообразие реальных вогнутых зданий и расстояний от точек до стен этой выборкой не покрывается.

Для неудачного кандидата в группе с допустимыми альтернативами обучающий индекс равен максимуму допустимых индексов плюс 2, но не ниже собственной нижней границы. Это искусственная метка предпочтения, не физический штраф и не правило отказа в подключении. Стандартизация обучена только на обучающей части. В исправленной модели масштаб почти постоянного признака (менее 1e-6) заменяется единицей: погрешность поворота геометрии около 1e-10 м больше не усиливается до полезного сигнала. Это исправление выявлено по статистике обучающих признаков, без использования эталонов реального квартала. Первоначальный эксперимент сохранён отдельно в `validation/neural/initial-experiment/`. Модель выбрана из девяти сочетаний размеров и seed по проверочной части; тестовые кварталы в выборе не участвовали. Оптимизатор выбранной модели достиг лимита 700 итераций: сходимость градиентного обучения не заявляется, предупреждение сохранено в отчёте.

Файлы: `server/src/main/resources/models/connection-ranker.json`, `tools/neural/data/`, `tools/neural/train.py`, `validation/neural-training-report.json`. Веса содержат происхождение данных, номера кварталов и SHA-256 всех файлов разметки. Идентичность Java-инференса и sklearn проверяется на 24 примерах отложенных территорий. Разметка сохраняется целиком атомарной заменой файла; перед обучением число строк каждого квартала сверяется с числом перебранных кандидатов, чтобы неполная запись не попала в обучение.

## Что показала проверка

На 16 тестовых кварталах выполнены три режима с одинаковыми настройками и исходной выборкой кандидатов:

| Режим | Кандидатов рассмотрено | Дорогих проверок кандидатов | Вызовов поиска маршрута | Время, с |
|---|---:|---:|---:|---:|
| `off`: исправленное ядро, без отсечения | 535 | 535 | 1 041 | 22,408 |
| `bounds`: аналитическая граница и отсечение | 535 | 443 | 953 | 18,814 |
| `on`: MLP и то же отсечение | 535 | 444 | 956 | 18,277 |

Все 16 кварталов полностью подключены во всех режимах. Итоговые индексы совпали с допуском 1e-6. Дополнительно регрессионный тест сравнивает сами геометрии, DN и индексы на квартале с общей сетью, препятствием, дорогой и обоими профилями оценки. 2 585 обучающих и отложенных записей проверены на непревышение аналитической границей фактического индекса допустимого кандидата.

Модель уменьшила среднее превышение индекса первого допустимого кандидата над лучшим в группе с 0,12875 до 0,04648 на тестовой части. Это улучшение порядка проверки, **не улучшение финальной трассы**. Отсечение уменьшило число дорогих проверок на 17,2%, а число поисков маршрута — на 8,5%. Дополнительного сокращения этих величин от нейросети нет.

Причина понятна: при неизменной выборке кандидатов и фиксированной нижней границе все конкуренты, чья граница не хуже лучшего индекса, всё равно должны проверяться. Сортировка по нижней границе уже может давать минимальное число таких проверок. Более точный прогноз сам по себе этого не меняет. Поэтому полученное ускорение нельзя приписывать обучению, а положительный результат по первому кандидату нельзя выдавать за улучшение проекта.

Полные журналы текущего сравнения — `validation/neural/ablation.json` и `ablation-summary.json`. Каждый режим дважды прогрет на отдельном квартале №999, затем порядок режимов чередуется; каждый планировщик имеет новый кэш. Параллельного большого расчёта во время замера не было. Это один проход по 16 территориям: разница 2,9% между `bounds` и `on` не доказывает устойчивого ускорения, тем более при трёх дополнительных поисках маршрута у модели. Более ранние результаты находятся в `initial-experiment/`; их первый замер включал прогрев JVM и не смешивается с текущей таблицей.

Рабочий результат на исходном квартале, сравнение с сохранённой предыдущей версией и независимая геометрическая проверка находятся в `validation/neural/` и в начале `VALIDATION.md`. Сравнение старого HTTP/H2-прогона и нового внутрипроцессного прогона не является контролируемым измерением ускорения.

## Результат на рабочем квартале

На неизменённых 144 объектах, 85 зданиях и 17 вводах гибрид дал три различных полностью подключённых варианта. Шесть порядков построения завершились с 17/17. Независимая проверка исходных концов, ближайших стен, всех остальных зданий, отступов, связности, стоимости, DN, глубин и поворотов пройдена (`validation/neural/independent-check.json`).

Но лучший прежний результат не сохранился: индекс 22,1643 → 26,8737 (меньше лучше), новая трасса 2 464,94 → 2 552,92 м, работы 368,750 → 482,561 млн ₽. Это ухудшение, поэтому гибрид не принят как улучшение рабочего алгоритма и не включён по умолчанию. Его геометрическая допустимость не означает экономического преимущества.

В этом прогоне проверено 1 307 кандидатов, 198 отсечено аналитической границей; сделано 2 643 вызова поиска маршрута, ошибок признаков нет. Время 1 567,720 с на внутрипроцессном стенде, 768 МиБ heap. Прежние 2 288,050 с получены через HTTP/H2/Chromium: это разные стенды, и такой разрыв нельзя выдавать за ускорение нейросети. Одновременно изменена работа поисковой области у ввода, поэтому ухудшение нельзя целиком приписать весам модели. Контроль на синтетических территориях выше изолирует ранжирование от этих изменений.

Дополнительный контроль отдельно запустил третий порядок построения с новым пустым кэшем: прежний JAR и исправленное ядро без нейросети дали точно одинаковую геометрию и индекс 27,786329; он совпал с соответствующим вариантом полного гибрида. Все допустимые нижние оценки этого контроля проверены. Это не воспроизводит историю кэша предыдущих порядков полного старого прогона и не доказывает тождественность всех режимов на реальной карте. Сводка — `validation/neural/order3-control.json`.

Модель обучена на локальных оценках существующих кандидатов. Она не исправляет жадный выбор топологии всей сети. Для следующего полезного эксперимента нужны новые маршруты и совместная оценка нескольких ветвей, а также примеры инженерских исправлений; простая перестановка тех же кандидатов преимущества в качестве здесь не дала.

## Устранённая зависимость от порядка

Первый полный эксперимент сохранил все 17 вводов, но потерял лучший прежний вариант: его индекс изменился с 22,1643 до 26,8679. Этот результат не принят как готовое улучшение. При анализе обнаружено, что поиск накапливал проверенные выходы из здания внутри `Gate.allowsInterior`; в результате изменение очередности кандидатов меняло область допустимого подхода и уже закэшированные проверки рёбер A*. Такой скрытый эффект мешал безопасно переставлять и пропускать кандидатов.

В режимах `off`, `bounds`, `on` функция `allowsInterior` проверяет геометрию без изменения состояния. Перед поиском `prepareSearch` определяет область подхода по фиксированной стене, DN и направлениям текущего запроса. Во время A* она постоянна. Проверка полного маршрута, повторное использование кэша и сглаживание используют точную `SpatialRules.assess` и проверку занятых ветвей, независимо от поисковой области предыдущего запроса. Область для сетки остаётся приближением; она не отменяет точную проверку длины конечного подхода и остальных стен.

Три регрессионные проверки фиксируют неизменность области после пробного луча, независимость готового маршрута от чужой поисковой области и совпадение маршрута после расчёта другой цели. Исходные ограничения стен, отступов и углов продолжают проходить существующие тесты. Обучающие примеры заново рассчитаны на исправленном алгоритме. Это изменение обычного поиска; его эффект нельзя приписывать обучению MLP. Само устранение зависимости не восстановило прежний лучший вариант. Режим `baseline` сохраняет старую область подхода и исходный порядок, без нейросети и отсечения; он остаётся основным для совместимости. Точная финальная проверка геометрии обязательна в каждом режиме.

## Почему нижняя граница допустима

Из пробной топологии вычисляются расходы и минимальные DN без повышения из-за длины. Повышение DN, специальные проходы и глубина не могут снизить цену. Для новой ветви и старых ветвей, которые могут быть перепроложены, используется хорда. Для старой ветви фактическую длину и внутренние повороты можно сохранить в границе только после проверки её геометрии при минимальном DN и следующем разрешённом DN: тогда `repairClearances` оставляет её без изменений. Проверяются оба диаметра, поскольку исключение для конечного подхода к своему зданию зависит от DN.

Стоимость реконструкции существующих труб определяется расходами и положениями врезок, которые для одного кандидата не меняются. Камеры оцениваются по минимальным DN; стоимость врезок известна из топологии. Неизвестные повороты присоединения не добавляются. При невозможности вычислить границу она становится нулевой — такой кандидат нельзя отбросить по оценке. Это локальное отсечение среди уже выбранных топологий, не доказательство глобального минимума всей сети.

## Как воспроизвести

Из корня проекта, с JDK 11+ и Maven:

```sh
mvn -f server/pom.xml test package
python3 tools/neural/run.py collect tools/neural/data 0 80
python3 -m pip install -r tools/neural/requirements.txt
python3 tools/neural/train.py
mvn -f server/pom.xml test package
python3 tools/neural/run.py benchmark validation/neural 64 16
python3 tools/neural/run.py supplied validation/neural on
python3 validation/verify_nearest_turns.py --output-name neural/supplied-neural-on --report-name neural/independent-check.json
```

Разметка и веса уже включены в архив: повторять обучение для запуска приложения не требуется. Python-harness требует Python 3.9+, повторное обучение с закреплёнными зависимостями — Python 3.11+. Для независимого валидатора нужны зависимости из `validation/requirements-check.txt`. Каждый вызов планировщика получает отдельный кэш. Прямой API позволяет сравнить `neuralGuidance=off|bounds|on`; в интерфейс новый переключатель не добавлен. По умолчанию действует `baseline`, сохраняющий прежний расчёт. Включение модели — явное `neuralGuidance=on`. Для изоляции эффекта обучения сравнивайте `on` с `bounds` на одном исправленном геометрическом ядре, а не с `baseline`.

## Что даст следующий этап

Текущий учитель не содержит инженерских исправлений и не знает новых топологий, поэтому ожидать от его копирования качественно лучшей сети необоснованно. Для улучшения формы нужен другой эксперимент: модель предлагает новые коридоры или выбирает несколько ветвей для совместной перепрокладки, а точный алгоритм проверяет их. Полезные данные — принятый и отвергнутый варианты одной территории, точные исправленные линии и причины предпочтения. Разделять обучение и тест нужно по целым территориям, включая сложные/вогнутые здания и большие расходы. Уменьшение времени и улучшение индекса необходимо проверять отдельно от доли полностью допустимых сетей.

Идея сочетания обучения с поиском подтверждается исследованием [Neural A*, Yonetani et al., ICML 2021](https://proceedings.mlr.press/v139/yonetani21a.html). В этой работе исследуется иной алгоритм; данный эксперимент не является реализацией Neural A* и не переносит его показатели скорости на теплотрассы. Использованный обучающий компонент описан в [документации MLPRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.neural_network.MLPRegressor.html). Выводы о пользе здесь основаны на сохранённых результатах нашего проекта.
