# Автоматическое обучение дерева 1.5.0

## Данные и цель

Используется существующая сеть 32 → 32 tanh → 1. Выход задаёт порядок проверок подключения. Инженерный расчёт и допуски не обучаются.

`TreeTrainingData` собирает два вида полных результатов:

1. При завершении дерева итоговый score после сглаживания приписывается действиям его пути. Для одного состояния сравнивается лучшее наблюдавшееся полное продолжение каждого действия.
2. При достройке последней точки, в том числе во время пересмотра ветви, сравниваются полностью проверенные кандидаты одного исходного состояния по score до сглаживания. Эти группы отделены от первого вида.

Метки не строятся по неполным сетям, неудачам поиска или непроверенным действиям. Для каждого состояния до 3 лучших наблюдённых действий сопоставляются с худшими; не более 32 пар на состояние. Ничьи и неразличимые признаки исключаются. Повторные пары не увеличивают объём опыта. Память ограничена 1024 парами на совместимый участок; старейшие вытесняются.

Цель — среднее `softplus(-(logit(a_good)-logit(a_other)))`. Это обучение предпочтениям, а не применение on-policy REINFORCE к отобранным деревьям. Для производных log-softmax используется уже проверенный градиент MLP; температура 1, энтропийная добавка не применяется. Adam, градиент ограничен по норме, небольшая регуляризация к исходным весам; движение весов за предложение ограничено L2=0.25. По умолчанию 16 шагов, скорость 0.001.

## Контроль принятия

Веса фиксированы в течение полного прохода дерева и пересмотра ветвей. Контрольный проход и следующий проход с копией используют одинаковые параметры поиска и не подмешивают сохранённый лучший вариант в список новых решений, используемых для сравнения моделей. Это предотвращает ложное принятие плохой модели за счёт старой хорошей сети.

Кандидат должен снизить ошибку на накопленных предпочтениях; затем полный поиск должен найти допустимую полную сеть со score не хуже контрольного в пределах 1e-8. При равном качестве веса могут быть приняты — это отображается как «качество сохранилось», а не как улучшение трассировки. При худшем/неполном результате или отмене сохраняются прежние рабочие веса. Геометрические кеши между проходами ускоряют повторные операции, поэтому длительности проходов не являются чистым сравнением скорости двух моделей.

Лучшие полные сети из всех проходов и прежнего опыта объединяются отдельно. Проверка кандидата никогда не затирает более успешную сохранённую сеть. Последний проход даёт новые примеры для следующего расчёта; непроверенная новая модель после последнего прохода не создаётся.

## Сохранение и диагностика

`tree-learning.json`: модель, Adam, число принятых шагов, число принятых моделей, число предложений и replay. Контрольная сумма, атомарная замена и резервная копия используют существующий ExperienceStore. Старый `training.json` и его pending-пакет остаются отдельными. В одну рабочую область пишет один расчёт под существующей блокировкой.

`search.treeLearning`: числовое изменение рабочих весов, размер памяти, обучающие пары, выполненные/принятые шаги, потери до/после, исходный/активный SHA и решения проверки. `search.treeSearch.passes` содержит результаты новых полных поисков; `qualityProgress` включает сохранённую лучшую сеть. Старое поле usedForTraining в попытках относится к on-policy RL; обучение предпочтениям описано отдельным блоком treeLearning.

Это локальная адаптация на данной территории. Никакой автоматической замены общей модели, обучения на чужих рабочих областях или заявления о переносе качества на новые карты нет. Обучение и проверка добавляют время; пользу следует оценивать по score, полному подключению, геометрии и общему времени, а не только по изменению весов.
