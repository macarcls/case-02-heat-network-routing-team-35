Длина, стоимость, score, повороты и длина реконструкции совпали с отчётом до численной погрешности. После этого полный Planner запущен с восстановленной сетью как сохранённым опытом. Снимок и сводка воспроизведения включены рядом.

## Воспроизведение

Из папки `server`:

```bash
mvn -Dtest=TreeTrunkSuppliedTest -DtreeTrunkSupplied=true -DskipTrunkRepair=true -DtrunkSeedSnapshot=../validation/junctions/reproduced-user-snapshot.json test
```

Отчёт и все три варианта: `validation/junctions-full/supplied-trunk-report.json` и `supplied-trunk.geojson`.
Независимая проверка из корня проекта:

```bash
python validation/verify_nearest_turns.py --output-name junctions-full/supplied-trunk --report-name junctions/independent-check.json
```

Нужны Python, Shapely и pyproj. Проверяются все три варианта: исходные вводы, фиксированные ближайшие стены, пересечения и отступы, ацикличность, DN, глубина, стоимость и штрафы поворотов.

Тесты: `test-results.json`. Проверка браузера и фактического ответа сервера: `ui-check.json`. Интерфейс и новый переключатель проверены на desktop и ширине 390 px. Docker и PowerShell в среде проверки не запускались; готовый JAR проверен через Java 11 и реальный HTTP-сервер с тестовой БД H2.

Исторические проверки в `validation/tree-trunk` относятся к 1.7.0. Основное сравнение этой версии — таблица выше.
